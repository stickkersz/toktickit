# Lab 3: AI Use and Reflection

**LLM/agent used:** Claude Code, Anthropic's command-line coding agent, running Claude Sonnet 5 and Claude Opus 5.5 in this repository's working directory for the whole Lab 3 sprint. I used it in two roles: as a **specification agent** that questioned me on the design and wrote the Sprint 3 contract (`docs/lab-03/`), and as a **coding agent** that implemented each Issue from that contract, tests first. A separate review agent I wrote in Lab 2 (`peer-review`) was used to review my partner's Pull Requests.

**How it was used, in one line:** the specification agent settled every design question with me before any code existed, the coding agent built one Issue at a time against that contract, and every decision that affects someone else (merges, posts to my partner, resetting the database, what to leave unfixed) stayed with me.

## My Reflection

**The specification agent.** Settling the design first worked: none of the seven decisions had to be reopened, and the traceability table meant every test had a reason to exist. But the contract the agent wrote still had real gaps, and my partner found them, not me. His first review of the contract (#38) asked me to clarify the password backfill sequence, and working through it showed the order as written could not work: the seed has to issue password hashes after the migration, not inside it. The contract also did not separate reading attachments from adding and removing them for IT Staff. A specification that looks complete is not the same as one that has been checked against the real data, and I only trusted it after the migration had been run on actual Lab 2 rows.

**The coding agent.** It was strongest when I made it prove things: tests written before the fix and shown failing on the old code, deliberately broken code to show a test really catches the bug, and screenshots read instead of just saved. Reading screenshots caught five places where Bootstrap's default blue leaked past the design tokens, and one screenshot captured halfway through a save. But the two hardest bugs of the sprint were ones my partner found and the agent did not: the status write on #51 that could be judged on one value and written on another, and the password change on #57 that could save the new password without ending the old sessions. Its own full review of Lab 3, the day before, had rated the session handling as solid. Green tests and an AI review never replaced a second person reading the code, and the decisions that mattered, such as what to fix now and what to record, when to merge, and what to tell my partner, stayed mine throughout.
